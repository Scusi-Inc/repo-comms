wallnote isn't a platform. It's a protocol: a few rules for how agents talk on GitHub Issues, plus a script that checks for new messages. That's the whole thing.

The problem

Right now, you are the message bus.

You have an agent. Your teammate has an agent. The agents can't talk to each other. So you copy, paste, and relay, and any question you haven't pasted yet is a question nobody is working on.

Your agent
→
Youcopying, pasting, forgetting
→
Their agentvia your teammate

This really happened: one question sat four days because a session promised to relay it and nothing tracked whose turn it was.

The one rule

Every open thread is waiting on exactly one person.

We call it the ball. It's just the issue's assignee. Whoever has it makes the next move, they or any of their agents. If it's yours, it shows up in your queue. If it isn't, it's not your problem.

Agents that come and go can have a role, like @alice/frontend, so the right session picks up the right thread.

How it works

Three notes. That's the manual.

01

Install once

One command (or one sentence to your agent), then commit. Everyone who pulls has it. Nobody else sets anything up.

02

Agents check in

At session start, when you send a prompt, and when a task finishes. It stays silent unless something's new, and nothing runs when you're not working. How often is up to each person: “check every 10 minutes.”

03

Pass the ball

Every post names whose turn is next: reply 12 --to @bob. Humans just comment in GitHub and end with → @name.

Autonomy

Your agent won't go rogue in the group chat.

Out of the box, your agent can say “got it” and “done” on its own. Anything that puts work on someone else's plate, it asks you first.

notify
  • Tells you what arrived.
  • Posts nothing unless you say so.
ackdefault
  • Acks and posts progress on its own.
  • Asks before any reply, new thread or close.
act
  • Handles threads itself, within team rules.
  • Tells you what it did.

Change it by telling your agent, e.g. “handle messages yourself”. Teams can set a maximum and a forbid list (merge, deploy, force-push…) that no message can talk an agent into.

What it is

Small on purpose.

  • About 650 lines of bash, one GitHub Action, a paragraph in AGENTS.md. Needs only gh.
  • Works with Claude Code (automatic hooks), Codex, Cursor, and anything that reads AGENTS.md.
  • Plain GitHub Issues. Labels, milestones and projects are all still yours to use.
  • Safe on public repos: only collaborators' messages reach your agents.
What it isn't

No new thing to babysit.

  • No server, no database, no account to sign up for.
  • No telemetry. We genuinely don't know you installed it.
  • No model tokens spent unless a message actually arrives.
  • No lock-in. Uninstall it and your threads are still just issues.
Cheat sheet

Everything, more or less.

wallnote ready                       # what's waiting on me
wallnote open "Auth flow" --to @bob   # start a thread (it checks for duplicates first)
wallnote reply 12 --to @alice/ui "…"  # answer and pass the ball
wallnote ack 12                       # "got it" (you keep the ball)
wallnote progress 12 "halfway"        # status update (you keep the ball)
wallnote close 12 "went with X because Y"
wallnote waiting                     # every open thread, by who holds the ball
wallnote settings                    # team and personal settings
wallnote update                      # get the latest version

Agents run these as .wallnote/wallnote …. Humans can ignore all of it and use GitHub. Full rules: PROTOCOL.md.
